# Приём заявок geokriolog.ru

Текущая версия: `2026-10-18-idempotent-v2`. Развёрнута 18.10.2026 как версия 2 существующего веб-приложения Google Apps Script. URL в `form-endpoint.json` сохранён. В истории Apps Script остаётся версия 1 для отката. Исходник версии 1 сверён через историю проекта с архивной копией перед изменением.

## Контракт

Сохраняются поля `name`, `phone`, `type`, `region`, `message`, `page`, тема письма `Заявка с сайта` и JSON `ok: true`. Новые поля: `request_id`, `direction`, `product`, `cta`, `source`, `first_landing_path`, `first_referrer_host`, `first_utm_source`, `first_utm_medium`, `first_utm_campaign`, `first_utm_content`, `first_utm_term`.

Для новых запросов обязательны корректный телефон и согласие. Поддерживаются оба старых имени ловушки спама: `_honey` и `_gotcha`. Старые открытые страницы без `request_id` принимаются совместимо; защита от повторов для них не гарантируется.

Клиент выполняет один POST на нажатие. Он сохраняет один ID после любой ошибки и не очищает поля. Направление и товар доступны для исправления посетителем. Первый источник сохраняется в пределах вкладки: путь без query/fragment, домен источника, пять разрешённых UTM. В цели Метрики контакты не передаются.

## Защита от повторных писем и учёт

Перед MailApp под общей блокировкой записывается `pending`. Повтор того же ID с тем же содержимым получает `ok:true, duplicate:true` только после состояния `sent`. Для `pending` возвращается `delivery_unknown`, для изменённого содержимого того же ID — `request_conflict`. Повторное письмо в этих состояниях не отправляется.

PropertiesService хранит ID, статус, время, направление и хеш полей. Контакты и текст заявки в этом журнале не хранятся. GET показывает только здоровье и версию. Письмо содержит полный контекст заявки для обработки в прежнем почтовом маршруте.

Если запись `pending` сохранена, а отправка не состоялась, автоматического восстановления нет. Это осознанная защита от неоднозначной доставки: проверить почту по ID, связаться по резервному каналу и разобрать запись вручную. Нельзя очищать `pending` и повторять запрос без проверки письма.

Записи не удаляются автоматически. Заполнение лимита PropertiesService прекращает отправку до записи нового состояния. Нужен периодический контроль объёма и перенос старых ID в постоянный журнал с сохранением проверки дублей; массовая очистка ID недопустима. Тесты не доказывают создание сделки в CRM: это проверяется отдельно.

## Проверка и выпуск

`node --test tests/lead-client.test.cjs tests/form-receiver.test.cjs` проверяет конкуренцию, потерю ответа, ошибки сохранения, валидацию, контекст и резервные контакты.

Сначала сохранить версию Apps Script, обновить существующее развёртывание, проверить GET с новой версией. Затем выпустить клиент и формы. Отдельным выпуском — тексты и предложения. Один сквозной запрос помечать «ТЕСТ — ИСКЛЮЧИТЬ ИЗ СТАТИСТИКИ» и подтверждать письмо плюс запись `sent`. Повтор с тем же ID должен дать `duplicate:true` без второго письма.
